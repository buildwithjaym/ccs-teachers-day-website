


# YOU MADE A DIFFERENCE — TEACHERS' DAY WEBSITE

Act as a senior frontend developer, UI/UX designer, and creative web designer.

Build a beautiful, emotional, modern, and fully responsive Teachers' Day website called:

# "You Made a Difference"

### Tagline:

**Every teacher leaves something behind.**

The website is created by students as a digital tribute to their teachers.

The goal is NOT to build a complicated platform. This is a simple, polished static website focused on one meaningful experience:

**Students can visit the website, choose a teacher, and read the messages written specifically for that teacher.**

---

# 1. TECHNOLOGY REQUIREMENTS

Use ONLY:

* HTML5
* CSS3
* Vanilla JavaScript

Do NOT use:

* React
* Next.js
* Vue
* Angular
* Tailwind
* Bootstrap
* jQuery
* Any frontend framework
* Any backend
* Any database

The website must work as a static website.

Use JavaScript for:

* teacher data
* message data
* teacher selection
* dynamic rendering
* navigation
* filtering
* animations
* mobile menu
* URL-based teacher pages if appropriate

# 17. RESPONSIVENESS — VERY IMPORTANT

The website MUST be responsive.

Design mobile-first.

It must work beautifully on:

* 320px phones
* 375px phones
* 390px phones
* 430px phones
* tablets
* laptops
* large desktop monitors

Do NOT simply shrink the desktop design.

Actually redesign layouts for mobile.

### Mobile requirements:

* navigation becomes hamburger
* cards become one column
* typography scales appropriately
* buttons become easy to tap
* images maintain correct proportions
* message cards fit naturally
* no horizontal scrolling
* no overflowing text
* no elements touching screen edges
* generous but appropriate spacing

Test the layout mentally at:

```text
320px
375px
768px
1024px
1440px
```

---

# 18. RESPONSIVE BREAKPOINTS

Use clean CSS media queries.

For example:

```css
/* Mobile */
default

/* Tablet */
@media (min-width: 768px)

/* Desktop */
@media (min-width: 1024px)

/* Large Desktop */
@media (min-width: 1440px)
```

Avoid creating dozens of breakpoints.

---

# 19. ANIMATIONS

Use subtle animations only.

Examples:

* hero text fade-up
* cards gently reveal on scroll
* image scale on hover
* button hover movement
* message cards fade in
* subtle envelope/paper movement
* smooth scrolling

Use CSS transitions and IntersectionObserver where useful.

Do NOT make everything move.

The website should feel:

**quiet, elegant, emotional.**

---

# 20. ACCESSIBILITY

Implement good accessibility:

* semantic HTML
* alt text for images
* proper heading hierarchy
* keyboard navigation
* visible focus states
* accessible buttons
* sufficient color contrast
* `aria-label` where appropriate
* reduced-motion support

Include:

```css
@media (prefers-reduced-motion: reduce) {
    * {
        animation-duration: 0.01ms;
        animation-iteration-count: 1;
        transition-duration: 0.01ms;
        scroll-behavior: auto;
    }
}
```

---

# 21. IMAGE HANDLING

All images should come from the `/images` directory.

Do NOT embed external image URLs.

Use meaningful image paths such as:

```text
images/teachers/maria-santos.jpg
images/teachers/juan-dela-cruz.jpg
images/hero/hero-classroom.jpg
```

Use responsive image behavior:

```css
img {
    max-width: 100%;
    height: auto;
}
```

Teacher portraits should use consistent aspect ratios.

Use `object-fit: cover` where appropriate.

---

# 25. URL BEHAVIOR

Teacher cards should open:

```text
teacher.html?id=maria-santos
```

The JavaScript should:

1. Read the `id` query parameter.
2. Find the teacher in `teachers.js`.
3. Display their information.
4. Find all messages belonging to that teacher.
5. Render those messages.
6. Enable category filtering.
7. Show an empty state if there are no messages.

If an invalid teacher ID is provided:

```text
teacher.html?id=does-not-exist
```

show a friendly error page:

> **We couldn't find that teacher.**

Button:

**Back to Teachers**
